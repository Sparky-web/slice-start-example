# Правила проекта

Правила обязательны для людей и ИИ-агентов. ESLint проверяет большую часть правил: `pnpm lint`. Остальное проверяет ревью по этому файлу.

## Команды

- `pnpm dev` — запуск приложения.
- `pnpm check` — полная проверка перед коммитом: токены, типы, линтеры, тесты, сборка.
- `pnpm lint:fix` — автоисправление.
- `pnpm --filter @repo/ui test:update` — обновить эталонные скриншоты.

## Документация в коде

Каждая экспортируемая функция, компонент, серверная функция и константа получает JSDoc. Каждое свойство в интерфейсе пропсов получает JSDoc.

JSDoc пишется на упрощённом техническом русском (УТР):

- Одно предложение — одна мысль. Предложение короче 20 слов.
- Действительный залог и настоящее время: «Сохраняет задачу», а не «Задача сохраняется».
- Без причастных и деепричастных оборотов.
- Без канцелярита: «является», «осуществляет», «данный», «в рамках», «посредством», «необходимо».
- Один термин для одного понятия. Задача всегда «задача», а не «тикет» или «карточка».

JSDoc описывает продуктовый смысл: что получает пользователь или бизнес. JSDoc не описывает реализацию.

- Нельзя: имена переменных, функций, компонентов и свойств, код, примеры использования.
- Нельзя: «Вызывает API и кладёт результат в кэш».
- Можно: «Список задач проекта. Новые задачи идут первыми».

Примеры использования живут в историях Storybook и тестах.

## Компоненты

- Компонент лежит в своей папке: `Button/Button.tsx`, рядом `Button.story.tsx`, `Button.test.tsx`, `screens/`.
- Пропсы описывает `interface ИмяКомпонентаProps` в файле компонента. Описание пропсов прямо в параметрах и через `type` запрещено.
- Компоненты собираются из `@repo/ui`. Цвета и размеры берутся из токенов.

## Типы

- `as` запрещён, кроме `as const`.
- Вместо `as` используйте:
  - `satisfies`, чтобы проверить литерал и сохранить точный тип;
  - аннотацию переменной: `const values: TaskInput = …`;
  - проверку типа: `typeof`, `in`, `instanceof`, функцию с `value is T`;
  - разбор через Zod для внешних данных: ответы сервисов, файлы, cookie, переменные окружения.
- Редкое исключение помечайте причиной: `// eslint-disable-next-line @typescript-eslint/consistent-type-assertions -- причина`. Без причины линтер не пропустит.

## Даты и время

- Только Temporal. `new Date()`, `Date.now()`, date-fns, moment и dayjs запрещены линтером.
- Полифил загружается в браузерах и на сервере без встроенного Temporal.
- Календарная дата без времени (срок, день рождения) — `Temporal.PlainDate`. Такая дата не сдвигается между часовыми поясами.
- Момент события (создание, вход) — `Temporal.Instant`. В базе и в ответах сервера момент хранится строкой с часовым поясом.
- Пользователь видит даты через компонент даты или форматирование из `@repo/lib` в своём часовом поясе.
- Часовой пояс выбирается так: настройка пользователя, затем настройка сайта `APP_TIME_ZONE`, затем пояс устройства.
- `Date` допустим только на границе с базой данных: Prisma принимает только `Date`.

## Списки и таблицы

Обе таблицы используют один контракт: запрос порции строк и ответ с найденными строками и общим числом.

- Сервер: схема запроса из общего хелпера проверяет вход, второй хелпер превращает запрос в выборку. Серверная функция описывает только условия доступа и вид строки.
- Клиент: `listQueryOptions` из `@repo/ui` строит описание списка для таблицы данных.
- Грид передаёт тот же запрос: порядок и текстовые фильтры колонок.
- Генератор серверных функций не используется. Компилятор TanStack Start находит серверные функции только на верхнем уровне модуля. Условия доступа должны быть видны в коде каждой функции.

## Архитектура

- FSD: `app → pages → widgets → features → entities → shared`. Слой импортирует только нижние слои. Слайсы одного слоя изолированы.
- Импорт слайса — только через его `index.ts`.
- Серверный код живёт в слайсе рядом с интерфейсом: папка `api` со серверными функциями.
- Prisma доступна только через `~/shared/db`.
- `useEffect` запрещён. Данные загружает роут или запрос, реакции живут в обработчиках событий, производные значения считаются при отрисовке.
